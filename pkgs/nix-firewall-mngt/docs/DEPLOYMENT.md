# Deploiement et integration NixOS

## Chemins systeme

L'application interagit avec les fichiers systeme suivants :

| Chemin | Role | Droits |
|--------|------|--------|
| `/etc/nixos/customConfig/firewall.nix` | Configuration du pare-feu generee | root |
| `/etc/nixos/customConfig/default.nix` | Module NixOS qui importe firewall.nix | root |
| `~/.config/nix-firewall-mngt/theme.conf` | Preference de theme utilisateur | utilisateur |

## Le fichier firewall.nix

Genere par l'application, ce fichier est un module NixOS standard avec des commentaires de metadonnees pour la persistance des noms de regles :

```nix
# Fichier genere par Nix Firewall Manager - Ne pas editer manuellement
# Generated by Nix Firewall Manager - Do not edit manually
# nfm:rule:SSH:tcp:22
# nfm:rule:HTTP / HTTPS:tcp:80,443
# nfm:rule:DNS:udp:53
# nfm:rule:Steam:both:27015-27030
{ lib, config, pkgs, ... }:

{
  networking.firewall = {
    enable = true;
    allowedTCPPorts = [ 22 80 443 ];
    allowedUDPPorts = [ 53 ];
    allowedTCPPortRanges = [
      { from = 27015; to = 27030; }
    ];
    allowedUDPPortRanges = [
      { from = 27015; to = 27030; }
    ];
    trustedInterfaces = [ "docker0" ];
  };
}
```

Les commentaires `# nfm:rule:...` sont ignores par Nix mais lus par l'application au prochain demarrage pour restaurer les noms de regles personnalises.

Ce fichier est importe par `customConfig/default.nix` via :
```nix
imports = [
  ./firewall.nix
];
```

## Injection automatique de l'import

Au premier lancement, si `default.nix` n'importe pas encore `firewall.nix`, l'application injecte automatiquement l'import.

La fonction `inject_firewall_import()` (dans `nix_parser.rs`) :

1. **Supprime** les lignes `networking.firewall.allowed*Ports` existantes dans `default.nix` pour eviter les conflits avec `firewall.nix`
2. **Detecte** si un bloc `imports = [ ... ];` existe deja dans le fichier
3. **Si oui** : ajoute `./firewall.nix` a la liste existante (cohabitation avec d'autres applications)
4. **Si non** : cree un nouveau bloc `imports = [ ./firewall.nix ];` apres la deuxieme accolade ouvrante du fichier

### Cas 1 : Aucun import existant

```nix
{ lib, config, pkgs, ... }:
{
  # L'import est injecte ici
  imports = [
    ./firewall.nix
  ];
  ...
}
```

### Cas 2 : Un bloc imports existe deja (autre application)

```nix
{ lib, config, pkgs, ... }:
{
  imports = [
    ./other-app.nix
    ./firewall.nix    # <- ajoute a la liste existante
  ];
  ...
}
```

## Flux de deploiement complet

### Depuis le code source jusqu'a la VM/machine

```
1. Developpement local
   nix-firewall-mngt/ sur la machine de dev

2. Push sur Framagit
   git push origin main
   → framagit.org/gaming-linux-fr/glf-os/app-glf-os/nix-firewall-mngt

3. Mise a jour du paquet dans glf-os
   glf-os/pkgs/nix-firewall-mngt/default.nix
   ├── Mettre a jour rev = "<nouveau-commit>"
   ├── Copier le Cargo.lock
   └── Mettre a jour hash = "<nouveau-hash>"

4. Reconstruction sur la machine cible
   nix flake update glf
   sudo nixos-rebuild switch
```

### Pour tester sur une VM

```bash
# Depuis la machine de dev (SSH vers la VM)
ssh glft

# Sur la VM
cd /etc/nixos
nix flake update glf
sudo nixos-rebuild switch
```

## Integration dans le systeme GLF-OS

### Arborescence dans glf-os (Framagit)

```
glf-os/
└── pkgs/
    └── nix-firewall-mngt/
        ├── default.nix    # Definition du paquet
        └── Cargo.lock     # Dependances verrouillees
```

### Le fichier default.nix dans glf-os

```nix
{ lib, stdenv, rustPlatform, fetchFromGitLab, ... }:

stdenv.mkDerivation rec {
  pname = "nix-firewall-mngt";
  version = "1.0.5";

  src = fetchFromGitLab {
    domain = "framagit.org";
    owner = "gaming-linux-fr/glf-os/app-glf-os";
    repo = "nix-firewall-mngt";
    rev = "<tag>";
    hash = "<sha256-hash>";
  };

  cargoDeps = rustPlatform.importCargoLock {
    lockFile = ./Cargo.lock;
  };
  ...
};
```

### Procedure de mise a jour du hash

1. Modifier `rev` avec le nouveau commit
2. Mettre `hash = ""` (chaine vide)
3. Lancer la reconstruction : `sudo nixos-rebuild switch`
4. Le build echoue et affiche le hash correct dans le message d'erreur :
   ```
   hash mismatch in fixed-output derivation:
     got: sha256-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX=
   ```
5. Copier le hash affiche et le mettre dans `hash = "sha256-XXX...="`
6. Relancer la reconstruction

## PolicyKit

La politique PolicyKit permet a l'application d'effectuer des operations privilegiees (copie de fichiers dans `/etc/nixos/`, execution de `nixos-rebuild`).

Le fichier de politique definit :
- **Action ID** : `org.glfos.nixfirewall`
- **Privilege requis** : `auth_admin_keep` (demande le mot de passe admin, garde la session)
- **Binaire autorise** : `@bindir@/nix-firewall-mngt` (substitue a l'installation)
- **GUI autorise** : oui (`allow_gui=true`)

En pratique, c'est le terminal (kgx) qui demande le mot de passe sudo lors de l'execution du script de rebuild, pas directement PolicyKit.

## Detection automatique du flake NixOS

Depuis la v1.0.4, le script de rebuild detecte automatiquement si le systeme utilise un flake NixOS. Si `/etc/nixos/flake.nix` existe, l'application extrait le nom de la `nixosConfiguration` et utilise `--flake "/etc/nixos#<nom>"` pour le rebuild.

Cela resout le probleme ou le hostname de la machine ne correspond pas au nom declare dans `nixosConfigurations` du flake (ex: hostname "UL" mais flake definissant "GLF-OS").

Sans cette detection, `nixos-rebuild switch` echouerait avec :
```
error: flake 'path:/etc/nixos' does not provide attribute 'nixosConfigurations."<hostname>"'
```

## Terminaux supportes

L'application tente d'ouvrir un terminal dans cet ordre de priorite :

1. **kgx** (GNOME Console) - terminal par defaut sur GLF-OS/GNOME
2. **gnome-terminal** - ancien terminal GNOME
3. **konsole** - terminal KDE
4. **xfce4-terminal** - terminal XFCE
5. **alacritty** - terminal GPU
6. **kitty** - terminal GPU
7. **xterm** - terminal X11 de base

### Limitation connue avec kgx

kgx (GNOME Console) entre en mode "Lecture seule" quand la commande se termine. Les commandes interactives comme `read` ne fonctionnent pas dans cet etat. C'est pourquoi le script affiche simplement "Vous pouvez fermer cette console." sans attendre de saisie.

## Depannage

### L'icone n'apparait pas dans la barre des taches GNOME

Verifier que :
1. Le fichier .desktop est nomme `org.glfos.nixfirewall.desktop`
2. Les icones sont installees sous le nom `org.glfos.nixfirewall.{svg,png}`
3. L'application ID dans `app.rs` est `org.glfos.nixfirewall`
4. Apres installation, executer : `gtk-update-icon-cache /usr/share/icons/hicolor/`

### Le rebuild echoue

- Verifier les logs dans le terminal qui s'ouvre
- Les erreurs courantes :
  - Conflit d'options NixOS si `default.nix` definit deja des ports firewall en parallele de `firewall.nix`
  - Erreur de syntaxe dans `firewall.nix` (ne devrait pas arriver avec le generateur)
  - Probleme reseau si nixos-rebuild doit telecharger des paquets

### Pas de terminal disponible

Si aucun terminal n'est installe, l'application affiche une banniere d'erreur. Installer au minimum `kgx` (GNOME Console) :
```nix
environment.systemPackages = [ pkgs.gnome-console ];
```
